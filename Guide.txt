============================================================
1. Общая идея проекта
============================================================

Проект «Реестр» — это веб-приложение для учёта и контроля:
- домов в реестре;
- активных отключений горячей воды и отопления;
- обращений граждан по вопросам ЖКХ;
- статистики и отображения объектов на карте.

Архитектура проекта:
- PHP отвечает за серверную логику и работу с БД;
- MySQL хранит данные;
- JavaScript получает JSON через API и обновляет интерфейс;
- Яндекс Карты используются для отображения адресов и координат.

Приложение предназначено для оператора поддержки, который может:
- фиксировать отключения;
- отслеживать статус дома и тип проблемы;
- добавлять и удалять дома из реестра;
- принимать обращения граждан;
- быстро искать записи по ID, адресу, телефону, типу или ФИО.

3. Как устроен поток данных
============================================================

Основной поток данных выглядит так:

1. Пользователь открывает одну из страниц: index.php, outages.php или appeals.php.
2. Страница подключает общий шаблон head.php / footer.php.
3. На странице создаются контейнеры, формы, таблицы и виджеты.
4. JavaScript делает запрос к public/api/index.php.
5. PHP API вызывает нужный репозиторий.
6. Репозиторий обращается к MySQL.
7. Результат возвращается в JSON.
8. JavaScript обновляет DOM, статистику и карту.

Схема: UI -> JS -> API -> PHP -> MySQL -> JSON -> JS -> интерфейс.

4. Конфигурация
============================================================

Файл src/config.php содержит базовые настройки.

Ключевые параметры:

- base_url

  Настройки подключения к MySQL:
  - host
  - port
  - name
  - user
  - pass
  - charset

- yandex_maps_api_key
  Ключ JavaScript API Яндекс Карт.
- yandex_geocoder_api_key
  Ключ HTTP Геокодера для подсказок адресов.

- map_center, map_bounds и map_zoom
  Центр, границы Омска и масштаб карты.

5. Инициализация приложения
============================================================

Файл src/bootstrap.php — это базовая инициализация всех PHP-скриптов.

Это место, где происходит:
- чтение конфигурации из config.php;
- создание единственного PDO-подключения к MySQL;
- автозагрузка классов репозиториев;
- функции JSON-ответов и ошибок;
- работа с сессиями и авторизацией;
- утилиты для чтения POST/JSON-тела запроса.

Основные функции:

- config()
  Возвращает массив настроек и кэширует его.

- auth_user()
  Возвращает данные текущего пользователя из сессии.

- login_user(array $user)
  Записывает пользователя в $_SESSION.

- logout_user()
  Очищает сессию и завершает вход.

- require_auth()
  Переводит пользователя на login.php, если он не вошёл.

- Database::pdo()
  Создаёт и возвращает singleton-объект PDO.

- json_response(array $payload, int $code = 200)
  Возвращает JSON с нужным HTTP-кодом.

- fail(string $message, int $code = 400)
  Возвращает ошибку в формате { ok: false, error: ... }.

- body_input()
  Возвращает данные из JSON или POST.

- get_stats()
  Считает текущую статистику по системе.

6. Схема базы данных
============================================================

Файл sql/reestr.sql содержит схему пустых таблиц без адресов и обращений-примеров.

1) Таблица houses

Это реестр домов.
Поля:
- id — идентификатор дома;
- address — адрес;
- lat, lng — широта и долгота;
- created_at — дата создания.

Уникальность адреса обеспечена через UNIQUE KEY, чтобы не было дублей.

2) Таблица outages

Это таблица отключений.
Поля:
- id — идентификатор;
- house_id — ссылка на дом;
- type — hot_water или heating;
- reason — причина сбоя;
- start_at — время начала;
- planned_end — предполагаемое время восстановления;
- is_active — активен или восстановлен;
- created_at — дата создания.

Типы отключений:
- hot_water — горячая вода;
- heating — отопление.

3) Таблица appeals

Это обращения граждан.
Поля:
- id — идентификатор;
- address — адрес;
- fio — ФИО заявителя;
- phone — номер телефона;
- lat, lng — координаты;
- created_at — дата создания;
- updated_at — дата изменения.

4) Таблица accounts

Это табличка для входа по логину и паролю.
Поля:
- id
- login
- password_hash
- is_active
- created_at

Администратор вручную добавляет сюда пользователей, которым разрешён вход.

7. API-модуль
============================================================

Файл public/api/index.php — это единая точка доступа к данным.

Параметры запроса:
- action — основной тип действий: stats, map, houses, outages, appeals
- op — операция: list, create, update, delete

Примеры:
- GET api/index.php?action=stats
- GET api/index.php?action=map
- GET api/index.php?action=houses&op=list&q=...
- POST api/index.php?action=outages&op=create

Логика файла:
- читает action и op;
- проверяет авторизацию;
- разбирает JSON-body;
- вызывает нужный репозиторий;
- возвращает JSON;
- ловит ошибки БД и серверные ошибки.

Сценарии:

- stats
  Возвращает общую статистику по системе.

- map
  Возвращает активные отключения и звонки для карты.

- houses
  list, create, update, delete.

- outages
  list, create, update, delete.

- appeals
  list, create, update, delete.

Дополнительно есть функции:
- self_lat() / self_lng() — обрабатывают координаты;
- self_datetime() — переводит дату в формат MySQL;
- self_validate_appeal() — проверяет адрес, ФИО и телефон.

============================================================
14. Авторизация и сессии
============================================================

Система входа сделана так:
- логин и пароль хранятся в таблице accounts;
- пароль хранится в виде bcrypt-хэша;
- при входе ставится PHP-сессия;
- на все страницы и API есть проверка require_auth();
- если пользователь не вошёл, он автоматически редиректится на login.php.

Файлы:
- public/login.php — страница входа;
- public/logout.php — выход;
- src/bootstrap.php — хранение и проверка сессии;
- src/repositories/AccountRepository.php — проверка логина и пароля.

Плюс этого подхода:
- администратор не создаёт пользователей через UI;
- нужные аккаунты добавляются вручную в SQL;
- система остаётся простой и безопасной для локального проекта.

============================================================
15. Полезные замечания по запуску
============================================================

Для нормальной работы нужно:
- запустить Apache и MySQL (например, через XAMPP);
- импортировать sql/reestr.sql в базу reestr;
- настроить src/config.php;
- убедиться, что проект доступен по адресу http://localhost/Reestr/;
- при желании получить Yandex API key для карты и подсказок.

Если ключа нет:
- карта не отображается;
- адресная подсказка не работает;
- остальной функционал работает.

Итог
============================================================

Проект «Реестр» — это небольшой CRUD-проект для ЖКХ-учёта, где:
- PHP отвечает за серверную логику;
- MySQL хранит данные;
- JavaScript обеспечивает интерактивность;
- карта и геокодер добавляют простую географическую привязку;
- авторизация закрывает доступ к системе.

Это проект, который можно использовать как основу для небольшого внутреннего инструмента оператора ЖКХ, диспетчера, либо поддержки.

Методы:

- list(?string $q = null, string $type = 'all', string $status = 'active')
  Очень важный метод. Он позволяет искать и фильтровать отключения:
  - поиск по ID;
  - поиск по адресу дома;
  - поиск по причине;
  - фильтр по типу hot_water / heating;
  - фильтр по активности: active, restored, all.

  Он умеет по русским словам искать тип отключения:
  - если в запросе есть 'вод', он понимает, что это про hot_water;
  - если есть 'отопл', значит heating.

- active()
  Возвращает только активные отключения, которые нужны для карты.

- create(int $houseId, string $type, ?string $reason, ?string $plannedEnd, string $startAt)
  Создаёт запись отключения.

- update(array $in)
  Частично обновляет запись: можно менять type, reason, planned_end, is_active.

- delete(int $id)
  Удаляет запись.

Роль этого модуля: фиксировать фактические аварии и ремонты, а затем показывать их в интерфейсе как активные или восстановленные.

12. Модуль карты и статистики: public/assets/js/main.js

Это главный клиентский сценарий главной страницы.

Основные функции:

- loadStats()
  Получает данные stats и анимирует числа.

- loadToday()
  Получает обращения за сегодня и показывает список звонков.

- initMap()
  Проверяет, есть ли Yandex Maps API.
  Если всё ок, отправляет запрос action=map и строит карту.
  Для каждого объекта создаёт Placemark и добавляет его в коллекции.

- showFallback()
  Если ключ API не задан или карта не загрузилась, показывает сообщение о том, что карта недоступна.

- bindLegend()
  Отслеживает переключатели слоёв на карте и включает/выключает их.

Подводный смысл:
- приложение не хранит карту в PHP;
- карта строится динамически по данным из массива объектов.

  Обрабатывает кнопки “Изменить” и “Удалить”.
  Если нажата кнопка “Изменить”, данные загружаются в форму.

- resetForm()
  Сбрасывает форму и очищает скрытые поля lat/lng.

- onSubmit(e)
  Сохраняет новое обращение или обновляет существующее.

Логика здесь очень прозрачна: форма работает в режиме “создать/редактировать”, а таблица служит списком существующих записей.

17. Общий JavaScript-утилитный модуль: public/assets/js/common.js

Это ядро фронтенд-утилит для всех страниц.

Здесь находятся функции:

- $ и $$
  Удобные обёртки для document.querySelector и querySelectorAll.

- esc()
  Экранирует HTML-символы, чтобы избежать XSS.

- hl()
  Подсветка поискового запроса в таблице.

- api(params, opts)
  Универсальная функция запроса к API.
  Она:
  - собирает URL;
  - делает fetch();
  - проверяет http status;
  - распаковывает JSON;
  - выбрасывает ошибку, если сервер вернул ok: false.

- toast(msg, kind)
  Показывает всплывающие уведомления пользователю.

- debounce(fn, ms)
  Задержка выполнения события при наборе текста.

- countUp(el, to)
  Анимация чисел на главной странице.

- fmtDT(s)
  Форматирует дату-время в читаемый вид.

- confirmSwap(btn, {...})
  Двухшаговое подтверждение на удаление.

- startClock()
  Запускает часы в шапке.

- loadBadges()
  Обновляет бейджи “активные отключения” и “звонки сегодня”.

- class AddressSuggest
  Очень важный модуль: он делает подсказку адресов через Яндекс Геокодер.
  Его работа:
  - слушает ввод пользователя;
  - после 3 символов вызывает API Яндекс;
  - получает варианты адресов;
  - показывает список;
  - при выборе адреса записывает координаты в скрытые поля lat/lng.

18. Принцип работы геокодинга и карт

Для адреса пользователю помогает Яндекс.

Процесс:
- пользователь вводит часть адреса;
- AddressSuggest отправляет запрос к geocode.api.yandex.ru;
- сервер Яндекса возвращает список найденных объектов;
- выбирается соседний вариант;
- в форму заносятся текст адреса, lat и lng;
- эти значения сохраняются в БД для домов и обращений.

Таким образом с помощью адреса можно:
- визуально показывать точки на карте;
- по координатам фильтровать и создавать метки;
- привязывать каждое обращение или отключение к географическому местоположению.

19. Логика скрытых полей lat/lng

В формах используется схема:
- visible input: адрес;
- hidden input: lat;
- hidden input: lng.

Это нужно для хранения координат и их передачи в API.

Пример:
- адрес: г. Москва, ул. Тверская, д. 12
- lat: 55.7661420
- lng: 37.5991720

После этого сервер сохраняет соответствующую пару координат и карта знает, где показывать объект.

20. Проверка данных и безопасность

На стороне сервера выполняется валидация:
- длина адреса не меньше 5 символов;
- ФИО должно содержать минимум фамилию и имя;
- номер телефона проверяется регулярным выражением;
- тип отключения должен быть только hot_water или heating;
- id должен быть корректным.

На стороне клиента тоже есть проверки, но PHP-валидация считается главной и обязательной.

21. Процесс создания нового отключения

Пример сценария:

1. Оператор выбирает дом из списка.
2. Указывает тип отключения: heating.
3. При желании указывает причину и плановую дату восстановления.
4. Нажимает “Зарегистрировать отключение”.
5. JavaScript собирает объект body:
   - house_id
   - type
   - reason
   - planned_end
6. API вызывает OutageRepository::create().
7. Запись добавляется в outages.
8. После этого обновляются:
   - таблица отключений;
   - список домов;
   - бейджи статистики;
   - карта главной страницы.

22. Процесс создания обращения

Пример сценария:

1. Оператор вводит адрес.
2. Выбирает его из подсказок Яндекс.
3. Указывает ФИО и телефон.
4. Нажимает “Сохранить”.
5. JS отправляет POST на API action=appeals op=create.
6. PHP валидирует данные.
7. AppealRepository::create() записывает в appeals.
8. Таблица обновляется, а доступные бейджи и статистика пересчитываются.

23. Почему проект структурирован так, а не иначе

У проекта очень простой и понятный паттерн:
- одна точка API;
- одна тема хранения данных — MySQL;
- репозитории как слой доступа к данным;
- JS как представление и взаимодействие с пользователем.

Плюсы такого подхода:
- можно легко расширять функциональность;
- все API-операции находятся в одном месте;
- логика запросов и бизнес-правила разделены;
- страницы фактически «толстые» только по интерфейсу, но не содержат SQL.

24. Что важно помнить при запуске

Для корректной работы проекта нужно:
- запустить Apache и MySQL в XAMPP;
- импортировать sql/reestr.sql в базу reestr;
- настроить src/config.php;
- убедиться, что URL указывает на /Reestr;
- при необходимости получить ключ Яндекс.Карт API.

При отсутствии ключа:
- карта не отрисовывается;
- подсказка адресов не работает;
- остальная логика продолжает работать.

26. Итог

Проект обеспечивает работу целого небольшого ЖКХ-репозитория: хранит дома, фиксирует отключения, учитывает обращения, показывает карту, ведёт статистику и даёт оператору простой способ работать в браузере.

Если смотреть на него как на программу, то это обычный CRUD-проект с небольшой аналитической и картографической логикой, в котором PHP отвечает за серверную часть, а JavaScript — за интерактивность и визуализацию.
